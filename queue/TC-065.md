**Context:** REQUIREMENTS §9.2 makes every HTML target "a backend of the same IR walk as
the SSG render, never a sibling interpretation". TC-021 landed `src/template/walk.ts` as a
sibling of `src/emit-server.ts`. The two copy each other's structural decisions:
`emitElement`/`openElement`, the plain-element, reactive-conditional and each-loop
handlers, the server conditional's arm iteration, `isComposeHostAttr`. They are held in
step only by the dump-target comparison. TC-062 settled the design with the owner on
2026-10-11. This task builds it. The rulings are below, so no architectural decision is
left to the contributor.

**Rulings (owner, 2026-10-11, recorded on TC-062):**

1. **One walk, a carrier for expressions.** `TemplateOp` becomes generic over its
   expression type, as `HtmlWriter<E>` already is. The walk produces
   `TemplateOp<Carrier>`. Every hole, condition test, loop source and include arg carries
   two things:
   - the authored node, which SSG lowers as JS (as it splices `exprText` today);
   - the walk's verdict, which is either a `PortableExpr`, or a non-portable reason plus
     its position class. A server value outside the subset is LTC057. A reactive initial
     value outside it routes the partial.
2. **The template side gets a total projection.** It is a shared function, not a
   per-target one: `TemplateOp<Carrier>` → `TemplateOp<PortableExpr>`. It is total
   because the walk has already refused (LTC057/LTC058) or routed every non-portable
   hole. Template targets, including `tests/targets/dump.ts`, see only the projected
   form. "Targets never see IR nodes" holds at the type level.
3. **The SSG backend owns only JS syntax plus module scaffolding:** header, imports and
   the `used` set, the render signature (including `__owner?`), setup emission, signal
   constructors, `refStub`s, `argsFromAttrs`, buffers and name minting. It consumes
   `TemplateOp<Carrier>` and keeps today's runtime sinks: `text`, `textOf`, `attr`, `esc`,
   `cls`, `styleAttr`, `sanitizeHtml`, `items`/`entries`, `composeHostAttrs`,
   `i18nRecord`, `clientLocale`, `clientMessages`, `isPending`, `witnessHarvest`.
4. **Operations only SSG lowers.** The walk takes over every construct `emit-server.ts`
   structures today, including the ones the template side cannot emit yet:
   - the synchronous `try`;
   - the async boundary with its driver state;
   - the reactive list: initial items, the `data-list` template, the list flags and the
     item setup;
   - the key-alias witness;
   - the children capture, with the owner arg and the `data-children` marker.

   The projection routes the SSG-only ones exactly as the walk routes those constructs
   today, so the template census does not change. TC-059 (boundary design), TC-060
   (lists) and TC-061 (children) later make their operations projectable.
5. **Walk once; specialize per locale.** The walk becomes locale-free:
   - message operations carry the key and the args;
   - the root's client `lang`/`i18n` becomes one operation.

   SSG lowers them to the runtime calls it makes today (`t`, `clientLocale`,
   `clientMessages`). For templates, one shared per-locale specialization step folds
   them, replacing today's walk-per-locale in `corpus.ts` `walkPartials`. Argument-less
   messages become literals, message calls become operations over the localized pattern,
   and the client record is precomputed through `changedClientForms`. A compose include's
   child locale resolves in that same step, replacing `childLocale`.
6. **Derived from the carriers:** skeleton retention for Simulated/Static
   (`retainReferenced`/`dropUnreferencedUnevaluable`) reads per-hole read sets from the
   carriers instead of re-parsing emitted strings with `identifiersIn`. Span recording
   reads carrier node offsets.
7. **What equivalence means (owner, recorded in REQUIREMENTS §12):** emitted module
   source may change shape. Rendered results and the content-security footprint may not.

**Do:**

- Implement rulings 1–6. Then delete every structural decision from `emit-server.ts`:
  after this task, it decides no markup structure, no attribute order and no escaping
  context.
- Keep the shared leaves where they are: `initialFold`, `isServerEvaluable`,
  `hostDerivedFold`, `armSetOf`/`isIf`/`elseOf`, `isBoundaryArmRoot`, `isVoidElement`,
  `children-region`. One copy of `isComposeHostAttr` remains.
- `listTemplate`'s reduced third element opener (`emit-server.ts`, `esc(String(x))` on
  server attrs, where `null` renders `"null"`) goes through the walk's one element
  opener. Its render output must stay identical, so if the opener's semantics differ
  there, preserve the list template's current output with an explicit operation
  attribute rather than changing it. Then report the divergence on the Review line.
- Do **not** fix TC-064 (`composeHostAttrs` class corruption) here. It is its own task,
  and this task's check is unchanged render output.
- Update module-source substring assertions (about 30 test files: compose, class-map,
  harness-alias, item-setup, key-alias-harvest, …) to the new module shape where the
  render is unchanged. Each update is a module-shape change, never a render change. If an
  assertion encodes a render fact, keep it and make it pass.

**Not in scope:** the boundary's authored form (TC-059), projecting the list template or
the children capture (TC-060, TC-061), the Twig target (TC-022).

**Channel/tier:** none. No check is added or removed, and LTC057/LTC058 keep their
sites.

**Check:**

  `tests/__snapshots__/` passes without regeneration (`AGENTS.md`), and so do

- The dump-target comparison in `tests/template-emission.test.ts` passes unchanged, and

- **Content-security footprint is unchanged:** generated server and client modules

- `emit-server.ts` contains no element-open, attribute-order or conditional-structure
  logic. State its remaining responsibilities on the Review line.
